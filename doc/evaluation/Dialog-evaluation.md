### Second golden set: real rendered prompt, one case, 70 rows

`src/database/judge_evaluation/judge_golden_set_worldcup.csv` (generated by
`src/main/studio/judge_eval/build_judge_golden_set_worldcup.py`) takes a different, more
directly testable shape: each row's `judge_input` column is the *exact* SystemMessage text
`judge_node`'s main decision call sends (captured by running the real `judge_node` with
`judge_llm` mocked, RAG forced empty), not just the raw state fields. This is what a runner
feeds straight to the judge LLM under test.

Run it against the real judge LLM and score `enough_evidence` accuracy with:

```
python main/studio/judge_eval/run_judge_golden_set.py      # from src/, or:
make judge-eval [GOLDEN_SET=worldcup] [LIMIT=<n>]
```

Results are cached to `judge_golden_set_worldcup_results.json` next to the CSV and
surfaced on the workbench's **Agents > Judge** page (not recomputed on page load, same
pattern as RAG ablation). There is deliberately only one CSV in
`database/judge_evaluation/` -- the golden set itself; results live in JSON only.

Each row's `category` column tags which casebook-theory situation it tests. `enough_evidence`
is about **coverage of the case, not quality of the answers** -- whether every stage the case
calls for was attempted, not whether the candidate did those stages well:

**Expected `False` (evidence incomplete):**
- `OPENING_ONLY` -- only the opening prompt + an unfounded first reaction.
- `STRUCTURED_NO_DATA` -- structure proposed, but the data block was never revealed.
- `DATA_MID_SYNTHESIS_NO_REC` -- data revealed and correctly read, but no recommendation reached yet.
- `PREMATURE_RECOMMENDATION` -- a recommendation given cold, with no structure or data behind it.
- `MATH_SKIPPED` -- recommendation reached, but the candidate never quantified anything the case calls for.
- `CREATIVE_SKIPPED` -- recommendation reached, but the case's creative/brainstorm question was never asked.
- `BOTH_EXHIBITS_SKIPPED` -- straight from synthesis to recommendation, no math and no creative question.
- `MATH_STARTED_NOT_FINISHED` -- the candidate starts the calculation but never reaches usable numbers.
- `RECOMMENDATION_ASKED_NOT_ANSWERED` -- the interviewer asks for a recommendation and the transcript ends there, unanswered.
- `OFF_TOPIC_CIRCULAR_LONG` -- many turns, but circular/generic, never actually progresses.
- `KEY_FACT_MISUNDERSTOOD_INCOMPLETE` -- candidate misreads a central case fact, isn't corrected, and the interview stops short.

**Expected `True` (evidence enough, regardless of performance quality):**
- `FULL_COVERAGE_STRONG` -- every stage covered, closely mirroring the case's ideal answer.
- `FULL_COVERAGE_WEAK` -- every stage covered, but generic/thin throughout.
- `FULL_COVERAGE_WITH_REDIRECT` -- every stage covered, after 1-2 interviewer nudges off a tangent.
- `FULL_COVERAGE_VERY_SHORT_EFFICIENT` -- every stage covered, compressed into very few turns.
- `FULL_COVERAGE_MATH_WRONG_BUT_ATTEMPTED` -- every stage covered; the math answer itself is wrong.
- `FULL_COVERAGE_CREATIVE_OVERSOLD_BUT_ATTEMPTED` -- every stage covered; the creative answer oversells the lever instead of sizing it.
- `FULL_COVERAGE_HALLUCINATED_DATA` -- every stage covered; the candidate invents an unsupported fact along the way.
- `FULL_COVERAGE_LONG_ITERATIVE_MANY_REDIRECTS` -- long, non-linear path (several tangents/redirects) that still reaches full coverage.
- `FULL_COVERAGE_RECOMMENDATION_NO_RISKS` -- every stage covered; the final recommendation itself skips risks/next steps.

### Results so far (worldcup golden set, real judge LLM)

| Prompt version | Rows | Accuracy | Precision | Recall | TP | TN | FP | FN |
|---|---|---|---|---|---|---|---|---|
| Original `judge_graph_system_prompt.md` | 50 | 76% | 81% | 68% | 17 | 21 | 4 | 8 |
| + explicit "coverage, not quality" + exhibit/recommendation-answered checks | 50 | 86% | 80% | 96% | 24 | 19 | 6 | 1 |
| Same prompt, golden set expanded to 70 rows (4x on the 3 weak categories) | 70 | **80%** | 73% | **94%** | 33 | 23 | 12 | 2 |

The dominant original failure was the judge conflating "enough evidence to evaluate" with
"the candidate performed well" -- it kept asking for a sharper recommendation, corrected
math, or explicit risks even when every stage had already been attempted (8 of the original
12 mismatches). Making that distinction explicit in the system prompt fixed 7 of those 8, and
holds up on the larger 70-row set (only 2 false negatives total, both the same
`FULL_COVERAGE_VERY_SHORT_EFFICIENT` edge case below).

The accuracy drop from 86% to 80% is **not** a regression -- it's the same prompt scored
against 4x more examples of exactly the categories it was already failing, which surfaces
their true failure rate instead of a noisy 2-sample estimate. Per-category breakdown on the
70-row set (mismatches / total):

- `MATH_SKIPPED`: **4/4 wrong** (100%) -- systematic, not noise.
- `CREATIVE_SKIPPED`: **4/4 wrong** (100%) -- systematic, not noise.
- `RECOMMENDATION_ASKED_NOT_ANSWERED`: **4/4 wrong** (100%) -- systematic, not noise.
- `FULL_COVERAGE_VERY_SHORT_EFFICIENT`: 2/4 wrong -- likely a golden-set design ambiguity
  (these transcripts have the candidate volunteer content, e.g. the creative answer or the
  recommendation, without the interviewer ever literally asking for it as its own turn), not
  a clean judge defect.
- All other 15 categories: **0 wrong**, 100% correct.

Three prompt-wording attempts (the "coverage not quality" framing, an explicit "check every
exhibit exists" instruction, and an explicit "asked is not the same as answered" clarification)
had zero measurable effect on these three categories across both the 50-row and 70-row runs.
This suggests the ceiling here isn't more prose in the system prompt -- it likely needs either
a more mechanical check (e.g. a second, narrowly-scoped LLM call or a deterministic pre-check
that lists case_data's exhibits and the transcript's last speaker before the main decision
call) or a stronger model. Not yet attempted.
